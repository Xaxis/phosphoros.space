# Phosphoros feature map

`../features.json` is generated by `featuremap` and never edited by hand. The
files here hold the recipes. Each one declares the ids it covers in a
`<!-- covers: -->` line, and `featuremap check` fails when an id has no recipe or
a recipe covers an id that no longer exists.

## Preconditions

`pnpm install` has run. Site recipes assume the site launched per ../SKILL.md on `$PORT`.
Never run `tools/deploy.sh` without `--check` unless you mean to deploy production, and never
dispatch GitHub Actions (none exist; the owner pays for minutes).

## Proof rules

- Drive the path a user takes. Mocks count only at a boundary production also has
  (a third-party API), never around the code being checked.
- A recipe lists every entry point. Proving one convenient entry point does not
  prove the others.
- An unreachable entry point is reported with its missing precondition. It is not
  counted as verified.
- A number is right only if it came from the model: compare the page with `pnpm calc --only <id>`.

## Areas

- [model](model.md): `pnpm calc` and the `@phosphoros/calc` package the site and tools import.
- [docs](docs.md): `pnpm docs` (ledger, bibliography, number links, generated tables) and the style check.
- [figures](figures.md): `pnpm figures`, `tools/look.ts` and the `@phosphoros/figures` package.
- [pages](pages.md): the home page, the section pages, the technology pages, the ledger and sources.
- [explore](explore.md): the in-browser Explorer.
- [metadata](metadata.md): manifest, robots, sitemap, icons and the share card.
- [deploy](deploy.md): `tools/deploy.sh`, Vercel and the domain checks.

## Entry contract

Each area file has: an H1, a one-line summary, a `<!-- covers: ids -->` line, then
exactly these sections: `## Sub-features`, `## How to reach it`, `## How to check
it`, `## Gotchas`. Keep it short enough to run without reading source. Split a
file once a section needs its own preconditions.
